# Пошаговое TDD для оплаты онлайн-магазина

Это **вторая версия** практической работы № 4, вариант 7. Она использует стиль небольших шагов, который Роберт Мартин показывает на примерах TDD. Это **не перевод исходного кода из видео**: предметная область здесь — интернет-магазин.

## Главный принцип

Нельзя сначала написать всю программу и только потом тесты. Повторяем для **каждой** новой возможности:

1. **RED:** добавляем **один** тест в `test_shop.py`; он падает, потому что поведение не реализовано.
2. **GREEN:** добавляем **минимум** кода в `shop.py`, чтобы новый тест прошёл.
3. **REFACTOR:** при необходимости упрощаем код; **все прежние тесты должны оставаться зелёными**.

Команда запуска:

```bash
python -m pytest -v martin_style_shop
```

## План 15 коротких циклов

| № | Написать тест (RED) | Минимальная реализация (GREEN) | Вариант рефакторинга |
|---|---|---|---|
| 01 | Пустая корзина = 0 | `total() -> 0` | Нет |
| 02 | Товар за 100 = 100 | `add()`, хранение цены | Понятные имена |
| 03 | Два товара суммируются | `sum(...)` | Избавиться от дублирования |
| 04 | Количество 3 умножает цену | Хранить количество | Кортеж `(price, quantity)` |
| 05 | Ноль товаров недопустим | Проверить `quantity` | Нет |
| 06 | Отрицательная цена недопустима | Проверить `price` | Объединить проверки |
| 07 | Скидка 25% | `set_discount()` | Вынести `subtotal` |
| 08 | Скидка 150% — ошибка | Проверить диапазон | Нет |
| 09 | Установить способ оплаты | `set_payment_method()` | Нет |
| 10 | Оплата 100 из 150 | `pay()`, статус paid | Упростить `pay()` |
| 11 | Пустой заказ оплатить нельзя | Проверка `items` | Нет |
| 12 | Недостаточно средств | Проверка `balance` | Нет |
| 13 | Нельзя оплатить дважды | Проверка статуса | Нет |
| 14 | Можно отменить неоплаченный заказ | `cancel()` | Объединить проверки статуса |
| 15 | Возврат и журнал событий | `refund()`, `events` | Упростить имена |

## Один цикл «вживую»: итерация № 1

**RED — пишем тест первым:**

```python
from martin_style_shop.shop import Shop

def test_01_new_shop_is_empty():
    shop = Shop()
    assert shop.total() == 0
```

Пока класса `Shop` нет, pytest сообщает ошибку импорта.

**GREEN — добавляем минимум кода:**

```python
class Shop:
    def total(self):
        return 0
```

Тест проходит, даже несмотря на то, что программа ещё не умеет добавлять товары! Для первого требования этого достаточно.

**REFACTOR:** упрощать нечего, двигаемся к тесту № 2. Именно тест № 2 заставит нас реализовать хранение цены.

## Как показать реальный процесс преподавателю

В `main` находится **готовое итоговое решение**. Чтобы доказать последовательность TDD, создайте отдельную ветку, например `tdd-step-by-step`, и воспроизводите 15 циклов по таблице. После RED можно сделать коммит `RED 01: ...`, после GREEN — `GREEN 01: ...`, после улучшений — `REFACTOR 01: ...` (если улучшение было). Не называйте историю публикации готового решения историей 15 реальных циклов TDD.
